글 / 사림이

보스가 공격을 준비할 때 바닥에 빨간 장판이 뜬다. 이때 내가 먼저 보는 건 빨강이 얼마나 강한지가 아니다. **유저가 어디까지 피해야 하는지, 아직 움직일 시간이 있는지 한눈에 읽을 수 있나?** 장판 하나를 그려도 이 두 질문의 답부터 정해두면 기획, VFX, 프로그래밍 사이에서 이야기가 훨씬 쉬워진다.

![어두운 바닥 위에 전체 범위가 표시된 사각 장판과 안쪽이 차오르는 원형 장판. 두 장판 안으로 바닥 타일이 비친다.](/images/postImage/crimson-telegraph.webp)

*왼쪽 / 바로 뜨는 직선 장판. 오른쪽 / 최종 경계 안쪽에서 차오르는 원형 장판. 장판의 읽힘을 설명하기 위해 만든 예시 이미지.*

## 크림슨 장판이란?

이 글에서 말하는 **크림슨 장판**은 보스 공격이 들어올 범위를 바닥에 미리 보여주는 **붉은 공격 예고 표시**다. 크림슨은 색, 장판은 바닥에 깔린 모양을 가리킨다. 구현이나 레퍼런스를 찾을 때는 `ground telegraph`, `attack telegraph`, `AoE indicator`도 같이 검색하면 된다. 공격 예고에는 보스의 준비 동작이나 소리도 포함되고, 여기서는 그중 바닥에 투사되는 표시를 다룬다.

- **모양 / 어디를 피할까?** 사각형은 돌진이나 직선 공격, 원뿔형은 휘두르기, 원은 지정 지점이나 보스 주변 공격을 표현하기 쉽다.
- **진행 / 언제 피할까?** 준비 동작, 안쪽 채움, 짧은 소리로 타격까지 남은 시간을 전달한다.
- **상태 / 이미 맞는 구간인가?** 예고가 끝나 타격이 발생하는 순간과, 타격 후 바닥에 계속 남아 피해를 주는 상태를 시각적으로 구분한다.

## 어디서 나온 표현일까?

공격 전에 위험을 전달하는 방식에는 준비 동작, 효과음, 색과 도형처럼 여러 갈래가 있다. 붉은 바닥 효과의 오래된 사례로는 《월드 오브 워크래프트》 4.1 패치가 있다. 여러 지속형 바닥 효과에서 적군이 만든 영역에 붉은 색조를 줘 아군 효과와 구별했다. 이 사례는 **위험과 소속을 색으로 읽게 한 예**다. [Blizzard / 4.1 패치 노트](https://news.blizzard.com/en-us/article/2657803/patch-4-1-rise-of-the-zandalari-updated-5-2)

공격 범위 자체를 바닥 도형으로 읽게 한 예로는 《WildStar》가 있다. 2013년 개발 영상에서 자유 조준과 피하기를 설명하면서 바닥에 표시되는 공격 범위를 보여준다. 두 사례는 붉은 위험 표시와 바닥 공격 예고가 어떻게 쓰였는지 보여준다. ‘크림슨 장판’이라는 이름을 누가 처음 썼는지는 확인하기 어렵다. [WildStar DevSpeak / Aiming](https://www.youtube.com/watch?v=kjQLsE02OPg)

## 바로 뜨는 장판 / 차오르는 장판

| 방식 | 처음 보이는 것 | 쓰기 좋은 상황 |
| --- | --- | --- |
| **바로 뜨는 장판** | 최종 외곽선과 내부 색이 처음부터 전부 보인다 | 짧은 돌진, 직선 베기, 여러 칸 중 안전한 칸을 빨리 골라야 할 때 |
| **차오르는 장판** | 최종 외곽선과 옅은 바탕을 먼저 보여주고, 내부의 붉은색이 타격 시점까지 차오른다 | 타이밍을 읽어 회피하는 큰 원형 공격, 방향을 고른 뒤 빠져나오는 부채꼴 공격 |

바로 뜬다는 건 **표시가 즉시 나온다**는 뜻이다. 타격까지는 유저가 방향을 읽고 이동할 시간이 있어야 한다. 사각 장판이라면 시작부터 끝까지 전체 폭을 보여주고, 돌진 시작 전까지 실루엣이 유지되게 한다. 예고 시간이 너무 짧게 느껴지면 대비를 올리기 전에 유저가 입력 잠금 중이었는지, 카메라에 장판 끝이 들어왔는지부터 확인한다.

차오르는 장판에서 나는 **외곽선은 범위, 채움은 시간**으로 나눈다. 원이 중심에서 퍼지더라도 처음부터 최종 반경을 알 수 있어야 바깥으로 나갈 경로를 고를 수 있다. 사각형은 한쪽 끝에서 반대쪽으로 채우고, 부채꼴은 중심에서 바깥으로 채우는 식으로 맞출 수 있다. 내부 채움의 앞쪽은 부드럽게 처리한다. 그래야 유저가 지금 보이는 색의 끝을 실제 타격 경계로 착각하지 않는다. 파동이 퍼지면서 지나간 위치마다 실제로 맞는 공격이라면 이동하는 피해 경계를 따로 보여준다.

## 원뿔형 장판 / 휘두르기는 옆 경계부터

![기계 보스의 발밑에서 두 직선이 벌어지고 먼 쪽을 둥근 호가 잇는 붉은 부채꼴 장판. 플레이어는 옆 경계 밖에 있다.](/images/postImage/crimson-telegraph-cone.webp)

*원뿔형 예시 / 바닥에서는 부채꼴로 보인다. 유저는 먼 호 밖으로 나가거나 가까운 옆 경계를 넘어서 피할 수 있다.*

원뿔형은 보스의 앞쪽을 넓게 쓸어 담는 공격에 쓴다. 바닥에 그릴 때는 보스 발밑의 **시작점 / 두 옆 경계 / 가장 먼 쪽의 호**가 보여야 한다. 내가 이 장판에서 먼저 보는 건 보스 바로 앞의 유저가 어느 쪽으로 한두 걸음 움직이면 빠져나오는지다. 보스 몸이나 다른 효과에 가려 옆 경계가 흐리면, 실제로는 옆으로 빠질 수 있어도 유저는 긴 호 바깥까지 달리기 쉽다.

휘두르기 방향이 확정되면 양쪽 선과 호를 그 자리에 유지한다. 그 뒤 안쪽을 차오르게 할 수도 있다. 공격이 실제로 한쪽부터 쓸고 지나가는 패턴이라면 타격 순서에 맞춰 부채꼴 안쪽을 옆에서 옆으로 채운다. 런타임에는 시작점과 바라보는 방향, 사거리, **양쪽 경계 사이의 전체 각도**를 같이 넘긴다. 전체 각도가 80도라면 중심 방향 양쪽으로 40도씩이다.

## 도넛형 장판 / 가운데가 안전한 원

![붉은 고리 사이로 바닥 질감이 비치고, 플레이어는 붉은색이 없는 중앙의 원 안에 서 있다.](/images/postImage/crimson-telegraph-ring.webp)

*도넛형 예시 / 반투명 크림슨으로 표시된 고리 부분이 위험 범위다. 가운데 바닥은 안전하다.*

원형 장판은 보통 안쪽이 위험하다. 도넛형은 반대로 **안쪽 선과 바깥쪽 선 사이만** 때린다. 그래서 중앙의 바닥색을 그대로 보여주고, 붉은색은 진짜 맞는 고리 부분에만 깐다. 보스나 이펙트에 중앙이 가려져도 안쪽 경계의 일부가 보여야 안으로 들어갈 수 있다는 걸 알아차린다.

바깥 경계 너머가 전장 안이면 그쪽도 안전하다. **중앙에서만** 피하게 만들려면 고리 바깥쪽이 전장 밖이거나, 바깥쪽 위험이 별도로 표시돼야 한다. 중앙이 실제로 유일한 안전지대라면 양쪽 경계의 읽힘에 더해, 가장 멀리 있는 유저도 예고 시간 안에 중앙까지 들어올 수 있는지 확인한다.

런타임에서는 원에 투명 마스크만 씌우고 판정을 그대로 두면 안 된다. 도넛형 타격은 `innerRadiusMeters`와 `outerRadiusMeters` 사이를 검사하고, 예고 렌더러도 같은 두 반경을 받아야 한다.

## 모양과 움직임별 장판 유형

원형, 직선형, 원뿔형은 **어디가 위험한지** 정한다. 차오름, 추적, 순차 폭발은 **그 위험이 언제 어떻게 바뀌는지** 정한다. 예를 들어 원뿔형은 바로 표시할 수도 있고, 최종 범위를 먼저 보여준 다음 안쪽을 차오르게 할 수도 있다.

| 유형 | 쓰는 패턴 | 유저가 읽어야 할 것 |
| --- | --- | --- |
| 일반 원형 | 내려찍기 / 지정 지점 폭발 | 원 안에 있으면 밖으로 나간다 |
| 도넛형 | 보스를 중심으로 한 주변 강타 | 붉은 고리 밖으로 벗어난다. 중앙도 대피 공간이다 |
| 직선형 / 사각형 | 돌진 / 레이저 / 직선 베기 | 긴 방향으로 달리기보다 가까운 옆 경계를 넘는다 |
| 원뿔형 / 부채꼴 | 브레스 / 전방 휘두르기 | 보스의 방향과 양옆 경계를 보고 옆으로 빠진다 |
| 반원 / 반쪽 장판 | 좌우 베기 / 전장의 절반을 가르는 공격 | 어느 쪽이 위험한지 보고 반대편으로 이동한다 |
| 십자형 / X자형 | 보스를 중심으로 뻗는 다방향 공격 | 팔 사이의 비어 있는 구간으로 들어간다 |
| 안전 쐐기 | 대부분의 각도를 때리는 회전 공격 | 여러 방향 중 비어 있는 좁은 각도를 찾아간다 |
| 격자형 / 타일형 | 발판 폭발 / 교대로 바뀌는 칸 | 현재 안전한 칸과 다음에 안전해질 칸을 구분한다 |
| 순차 장판 | 따라오는 연속 폭발 / 차례로 터지는 원 | 어느 위치가 먼저 터지는지 보고 빈 구간으로 이동한다 |
| 추적 장판 | 대상에게 붙는 폭발 / 마지막 위치에 낙하 | 장판이 따라오는 동안 위치를 빼고, 조준이 잠긴 뒤 범위를 벗어난다 |
| 확장 파동 | 중심에서 바깥으로 퍼지는 충격파 | 실제 맞는 경계가 움직인다. 고정 원 안의 카운트다운과 다르게 읽혀야 한다 |
| 지속 장판 | 타격 뒤 남는 불길 / 독 웅덩이 | 이미 피해가 활성화됐다. 경계가 사라지거나 비활성 표시가 나올 때까지 피한다 |

종류가 늘어날수록 색을 하나씩 더 배정하기보다, 같은 의미에는 같은 규칙을 쓴다. 예를 들어 바깥선은 실제 경계, 안쪽 채움은 준비 진행, 깜빡임이 끝난 뒤 남는 다른 질감은 지속 피해로 사용할 수 있다. 순차 장판은 모든 위치를 같은 세기로 보여주면 한꺼번에 터진다고 읽히니, **지금 터질 위치 / 그다음 위치**의 강도를 분리한다.

## 최근 사례에서 볼 만한 것

2026년 3월 《Cloudheim》의 Haven 업데이트는 공격 예고 데칼의 가시성을 개선했다고 밝혔다. 2024년 《드래곤 에이지: 베일가드》는 근접 위협을 캐릭터 주변 표시로, 원거리 위협의 방향을 선으로 전달하고, 일부 시각 신호에는 오디오 보조도 제공했다. 두 사례에서 내가 가져오고 싶은 건 **바닥 표시를 작게 봐도 읽히게 하고, 놓치기 쉬운 정보는 다른 신호로 한 번 더 전달한다**는 점이다. [Cloudheim / Haven 업데이트](https://store.steampowered.com/news/app/2070270/view/541132417437532244) / [EA / 접근성 소개](https://www.ea.com/games/dragon-age/news/accessibility-spotlight)

실제 화면에서는 붉은 장판 위로 아군 스킬과 보스 이펙트가 동시에 올라온다. 이때 위험 표시를 또 붉게 만드는 것보다 **얇은 경계 / 바닥과의 밝기 차이 / 차오르는 방향 / 타격 직전 소리**를 같이 쓰는 편이 정보를 나누기 좋다. 밝은 바닥, 붉은 바닥, 축소된 화면, 색각 필터에서 같은 경계가 읽히는지는 꼭 따로 본다.

## VFX 제작 요청 예시

> 보스 공격 범위를 바닥에 투사된 붉은 빛으로 표현해주세요. 내부는 반투명 크림슨으로 채우고 색과 투명도에 아주 완만한 그라데이션을 넣어 타일 줄눈과 바닥 결이 그대로 읽히게 해주세요. 실제 타격 범위에는 내부보다 밝은 코랄 레드의 얇은 외곽선을 그려주세요. 글로우는 외곽선 바로 주변에만 두어 빛이 바닥 표면에 붙어 보이게 해주세요.
>
> 바로 뜨는 타입은 첫 표시부터 최종 범위 전체가 보여야 합니다. 차오르는 타입은 같은 최종 외곽선을 첫 표시부터 유지하고, 내부만 타격 시점에 맞춰 채워주세요. 채움의 이동 경계는 바깥 외곽선보다 약하게 처리해주세요.

엔진에서는 평평한 바닥 위의 메시나 바닥에 투사하는 데칼을 쓸 수 있다. Unity URP 데칼을 쓴다면 바닥에만 투사되도록 받는 오브젝트를 확인한다. 계단 끝에서 아래층에 잘못 찍히거나 캐릭터 위로 빨간색이 묻으면 실제로 피해야 할 위치가 다르게 읽힌다. [Unity / 데칼의 Rendering Layers 설정](https://docs.unity3d.com/kr/Packages/com.unity.render-pipelines.universal%4015.0/manual/features/rendering-layers.html)

```json
  "startTick": 18000,

  "presentation": {
    "style": "crimson",
    "fillMode": "radial",
    "showFinalOutline": true
  }

```

- **표시 / 타격** 전투 시스템에서 확정한 동일한 범위를 예고 렌더러와 타격 판정이 사용한다. 클라이언트가 애니메이션 진행률로 피해나 반경을 결정하지 않게 한다.
- **동기화** 클라이언트는 동기화된 서버 틱 기준으로 `clamp((현재 틱 - 시작 틱) / (타격 틱 - 시작 틱), 0, 1)`을 구해 내부를 채운다. 시작 틱과 타격 틱이 다른 예고 구간을 기준으로 계산한다. 예고가 늦게 도착해도 현재 진행률부터 그린다. 이미 타격 시간이 지난 시작 이벤트로는 예고를 다시 띄우지 않는다.
- **즉시 표시** 직선 공격은 확정된 위치, 방향, 폭, 길이를 전달하고 `fillMode`를 `full`로 준다. 첫 프레임부터 전 범위를 표시하고 타격 시간은 똑같이 전투 시스템에서 받는다.
- **취소 / 갱신** 시전이 끊기면 같은 공격 ID로 취소 이벤트를 보내 장판을 내린다. 조준이 움직이는 패턴은 서버가 위치 갱신과 확정 시점을 정하고, 클라이언트는 같은 ID의 최신 리비전만 반영한다.

## 화면에서 마지막으로 볼 것

- **경계** 안쪽과 바깥쪽에서 한 발씩 움직여 본다. 흰 줄이나 지형 경계에 겹쳐도 외곽선이 보이는지, 발 위치를 기준으로 예상한 결과와 판정이 맞는지 확인한다.
- **타이밍** 같은 공격을 여러 프레임레이트와 네트워크 지연에서 본다. 차오르는 장판이 다 찬 것처럼 보이는 순간과 실제 타격 사이에 유저가 체감할 만큼 차이가 나는지 확인한다.
- **겹침 / 정리** 장판 두 개와 아군 효과가 겹쳐도 각 경계와 안전한 공간을 구분할 수 있어야 한다. 시전 취소, 보스 사망, 다음 페이즈 전환 때 장판이 남지 않는지도 본다.

장판을 처음 보는 사람에게 캡처 한 장을 보여주고 “어디로 피할 건가요?”라고 물어보면 범위가 읽히는지 바로 알 수 있다. 그다음 짧은 영상을 보여주고 “언제 움직일 건가요?”라고 물어본다. 두 답이 내가 의도한 패턴과 맞아떨어질 때 크림슨 장판이 제 역할을 한다.
